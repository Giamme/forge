`forge handoff resume` holds the plan's lock while it saves and resets the worktrees of stale `RUNNING` tasks, so a `run` started at the same moment is refused instead of racing the git reset and the status write. When another forge command already holds the lock, resume names it and changes and starts nothing (`"locked": true` in `--json`) (#157).
