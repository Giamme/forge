`forge setup` gets forge ready in one short pass, right after `forge install` on a terminal and again any time: it shows which agent CLIs are on this machine and which models each one runs, then asks for the models that build and review (the `balanced` profile first, or a pick per tier), the review threshold and shadow review, the defaults for `--sweep`, `--file-issues` and `--reviewer-session`, brief, summaries and retro with the model each needs, forge-ui (ask, always or never; read-only or with controls), whether this repository's `.forge/` memory is committed, kept local or off, decision models, storage, the update check and Ripwire. The answers become defaults, so the first `/forge` run asks none of it. `forge setup show` lists every answer, where it is stored and the command that changes it; `forge setup --defaults` takes the recommended answers and `forge setup export` / `--from FILE` copy them to another machine, all without a prompt. Setup never calls a model and sends nothing unless an answer says it will. Install no longer asks about Jev itself, and `forge update` never runs setup. Changing brief, summaries or retro now says it only reaches runs planned afterwards, and `forge control set <plan> summaries-model <spec>` changes a planned run's summaries model.
