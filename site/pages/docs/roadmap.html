What's coming

forge is developed in the open, mostly with forge itself. This is what's merged on the dev branch but not released yet, and what's planned. Plans change; the issue tracker is the source of truth.

On the dev branch

Group review
Related tasks share one reviewer over their combined diff (plan --groups waves --group-review). Each finding goes back only to the task whose files it names, the group merges in one step once it passes, and a finding that names no task stops the group for your decision. #140
Brief proposals
Brief questions can cover a wave or the whole plan, and an answer becomes a proposal. Nothing changes until you approve its exact diff by hash; a plan proposal can add, remove or split tasks. #136
Reviewer-session sampling
plan --reviewer-session-rate R continues the reviewer's session on a sampled share of tasks, so one run compares continued and fresh review rounds. #116

Planned

Resume from any CLI
A forge handoff summary that lets any agent CLI pick up a detached run: start it in Claude Code, finish it in Codex, without a second scheduler or repeated questions. Planned for 0.19. #146
Decomposition at every level
Goal to plans to tasks to subtasks with the same rules throughout, native to forge. Each split is a recorded decision within depth and size limits you approve up front, and forge-ui shows the whole tree. #153. It replaces the optional Fractal runtime, which will be removed. #154
Chained plans
Start a plan from another plan's integration branch. #143
Scripted tasks
A plan row that runs a repository command instead of a model. #142
A budget per tier
An escalated model gets attempts of its own. #141
Commands from forge-ui
Run forge's commands from the page, and remove worktrees and memories in bulk. #147
Steering a live dwarf
An investigation into prompting a running dwarf from forge-ui, harness by harness. #134
