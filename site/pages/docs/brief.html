Questions before a task

A dwarf can't stop and ask you anything mid-run. Three opt-in features close that gap: brief mode asks first, task summaries keep you informed, and retro notes tell you what got in the way.

Brief mode

Before each task starts, a cheap read-only model reads the plan and writes the questions only you can answer, each with why it matters, a few options, and the default forge will assume if you don't answer. Your answers go into that task's prompt as decisions you made.

/forge "add auth: tokens, middleware, login" --decompose-level medium \
  --profile balanced --brief gated --brief-model haiku:medium
LevelWhat waits
advisoryNothing. Unanswered questions reach the prompt with their defaults.
gatedA task with an unanswered must-answer question is held until you answer. The rest run.
strictThe whole run waits while any question of a task that hasn't started is open.
 
forge brief show "$PLAN"                                       # open questions, flagged first
forge brief answer "$PLAN" login-route q1 "one message for both cases"

You can also answer in forge-ui's inspector. Answer while earlier waves run: an answer that lands after its task started is kept as late, and forge prints the command to queue a follow-up. When a merge changes files a waiting task depends on, that task's open questions are flagged as possibly stale. forge never answers for you and never picks the brief model.

On the dev branch Questions about a whole wave or plan, whose answers become plan changes you approve by their exact diff (#136).

Task summaries

A few plain sentences per task, plus one line for the task table, written by a cheap model from the task's facts only: its status, attempts, verdicts and findings. It never sees your code. A summary is rewritten only when those facts change.

/forge "..." --decompose-level medium --summaries on --summaries-model haiku:low

forge control set "$PLAN" summaries on               # switch it during or after a run
forge control set "$PLAN" summaries off --task docs  # or per task

forge-ui shows each summary in the task inspector with its model, time and sources, and marks one out of date once the task has moved on.

Retro notes

With --retro (or forge config set retro on), builders and reviewers note what got in their way: a missing tool, a flaky test, a sandbox that blocked a command, a wrong instruction. Each note carries its command and error and is checked against the run's own logs.

forge retro report "$PLAN"   # retro.md: forge's problems, your project's, the environment's
forge retro issues "$PLAN"   # drafts redacted issues for forge's own repository

Nothing leaves your machine unless you approve a draft by its hash. The notes are about your setup as much as forge's: a missing dependency or a slow test lane shows up there too.
